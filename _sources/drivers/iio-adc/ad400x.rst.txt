Description
-----------

Analog Devices :adi:`AD4000` and the above listed devices are high
accuracy, high speed, low power SAR ADCs.

This is the Linux industrial I/O (:external+system-level:ref:`iio`) subsystem
driver, targeting single channel SPI interface :adi:`AD4000` and
similar ADC devices. The industrial I/O subsystem provides a unified framework
for drivers for many different types of converters and sensors using a number of
different physical interfaces (I2C, SPI, etc). See
:external+system-level:ref:`iio` for more information.

See the
:dokuwiki:`Evaluating AD400X and ADAQ400X devices </resources/eval/ad400x-eval-board>`
user guide for instructions on how to setup and evaluate devices supported by
the ad4000 Linux driver.

Adding Linux driver support

Kernel configuration
~~~~~~~~~~~~~~~~~~~~

Configure kernel with ``make menuconfig`` (alternatively use ``make xconfig`` or
``make qconfig``)

.. note::

   The driver depends on CONFIG_SPI and selects IIO_BUFFER,
   IIO_BUFFER_DMAENGINE, IIO_TRIGGERED_BUFFER and SPI_OFFLOAD.

::

   Linux Kernel Configuration
       Device Drivers  --->
           ...
           <*>     Industrial I/O support --->
               --- Industrial I/O support
               ...
               Analog to digital converters  --->
                   ...
                   <*>   Analog Devices AD4000 ADC Driver
                   ...
               ...
           ...

Driver setup
~~~~~~~~~~~~

AD4003/AD4007/AD4011/AD4020 are high speed analog-to-digital converters with
sample rates up to 2 MSPS. On FPGA-based platforms the device is driven
through the following HDL components:

- :external+hdl:ref:`spi_engine`
- :external+hdl:ref:`axi_dmac`

The devicetree binding requires ``compatible``, ``reg``, ``vdd-supply``,
``vio-supply`` and ``ref-supply``. ``adi,sdi-pin`` describes how the ADC SDI
pin is wired (``high``, ``low``, ``cs`` or ``sdi``); ``cnv-gpios`` gives the
GPIO connected to the CNV pin when the host drives it directly. ADAQ4001 and
ADAQ4003 additionally support ``adi,gain-milli`` to describe the hardware gain
set by the external resistor network, and ``adi,high-z-input`` to select
High-Z input mode (only available when ``adi,sdi-pin`` is not set, i.e. SDI
tied to MOSI).

.. code-block:: dts

   #include <dt-bindings/gpio/gpio.h>
   spi {
       #address-cells = <1>;
       #size-cells = <0>;
       adc@0 {
           compatible = "adi,ad4020";
           reg = <0>;
           spi-max-frequency = <71000000>;
           vdd-supply = <&supply_1_8v>;
           vio-supply = <&supply_1_8v>;
           ref-supply = <&supply_5v>;
           adi,sdi-pin = "cs";
           cnv-gpios = <&gpio0 88 GPIO_ACTIVE_HIGH>;
       };
   };

   spi {
       #address-cells = <1>;
       #size-cells = <0>;
       adc@0 {
           compatible = "adi,adaq4003";
           reg = <0>;
           spi-max-frequency = <80000000>;
           vdd-supply = <&supply_1_8v>;
           vio-supply = <&supply_1_8v>;
           ref-supply = <&supply_5v>;
           adi,high-z-input;
           adi,gain-milli = /bits/ 16 <454>;
       };
   };

See the
:dokuwiki:`Evaluating AD400X and ADAQ400X devices </resources/eval/ad400x-eval-board>`
user guide for examples of device trees used with devices supported by the
ad4000 Linux driver.

Configure sampling rate
~~~~~~~~~~~~~~~~~~~~~~~

The sampling-frequency attribute exists only when the ADC is driven through
SPI offload, and is per channel: ``in_voltage0-voltage1_sampling_frequency``
for differential parts such as AD4003/AD4007/AD4011/AD4020/ADAQ4001/ADAQ4003,
or ``in_voltage0_sampling_frequency`` for pseudo-differential parts such as
AD4000. Without SPI offload, an IIO trigger paces capture and there is no
sampling-frequency attribute.

::

   root@analog:~# cat /sys/bus/iio/devices/iio:device1/in_voltage0-voltage1_sampling_frequency
   2000000
   root@analog:~# echo 1000000 > /sys/bus/iio/devices/iio:device1/in_voltage0-voltage1_sampling_frequency
   root@analog:~# cat /sys/bus/iio/devices/iio:device1/in_voltage0-voltage1_sampling_frequency
   1000000

Buffer Example
~~~~~~~~~~~~~~

When the buffer is enabled, the ad4000 driver prepares a read transfer and
configures the :external+hdl:ref:`spi_engine offload` module to repeat that
transfer each time the offload module is triggered. Then, the driver sets
a PWM device to trigger the offload module at the rate specified by the
``sampling_frequency`` attribute. With that, ADC readings are gathered
continuously while the buffer remains enabled.

::

   root@analog:~# echo 1 > /sys/bus/iio/devices/iio:device1/scan_elements/in_voltage0-voltage1_en
   root@analog:~# cat /sys/bus/iio/devices/iio:device1/scan_elements/in_voltage0-voltage1_en
   1
   root@analog:~# echo 1 > /sys/bus/iio/devices/iio:device1/buffer/enable
   root@analog:~# cat /sys/bus/iio/devices/iio:device1/buffer/data_available
   32768

Data interpretation
^^^^^^^^^^^^^^^^^^^

Each buffer entry contains one sample. The amount of bits and their meaning will
vary according to ADC precision and output code pattern (whether output code is
twos complement or not). Buffer raw data may be retrieved by reading the
character device associated with the ADC device.

::

   root@analog:~# hexdump -n 512 -e ' 32 "%d " "\n"' /dev/iio:device1
   4864 4889 4730 4716 4695 4678 4667 4659 4662 4676 4706 4738 4770 4789 4786 4785 4775 4763 4752 4737 4723 4703 4686 4673 4666 4672 4688 4715 4762 4799 4820 4821
   4816 4807 4788 4773 4757 4737 4718 4694 4676 4664 4668 4692 4727 4777 4814 4837 4836 4829 4822 4808 4796 4771 4748 4728 4707 4685 4664 4654 4651 4659 4675 4709
   4757 4801 4823 4826 4812 4800 4789 4770 4749 4724 4700 4677 4653 4644 4633 4639 4659 4695 4738 4777 4798 4799 4794 4785 4772 4755 4735 4712 4692 4668 4652 4646
   4641 4648 4674 4709 4753 4793 4817 4818 4808 4797 4780 4764 4748 4724 4699 4674 4656 4639 4627 4633 4644 4677 4716 4765 4794 4804 4801 4791 4778 4763 4744 4721

Remove the ``-n`` parameter to keep reading the buffer continuously. To stop
capture, disable the buffer by writing 0 to
``/sys/bus/iio/devices/iio:device1/buffer/enable``.
