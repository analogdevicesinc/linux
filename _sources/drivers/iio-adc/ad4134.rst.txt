Adding Linux driver support
---------------------------

Kernel configuration
~~~~~~~~~~~~~~~~~~~~

Configure kernel with ``make menuconfig`` (alternatively use ``make xconfig`` or
``make qconfig``)

.. note::

   The AD4134 Driver depends on **CONFIG_SPI**

::

   Linux Kernel Configuration
       Device Drivers  --->
           ...
           <*>     Industrial I/O support --->
               --- Industrial I/O support
               ...
               Analog to digital converters  --->
                   ...
                   <*>   Analog Devices AD4134 ADC driver
                   ...
               ...
           ...

Follow the **Configuring the SD Card for FPGA Projects** section of the
:external+system-level:ref:`kuiper` page.

Copy the following files onto the BOOT partition to configure the SD card:

- **BOOT.BIN**: Binary blob file which includes first stage boot loader and FPGA
  bitstream.
- **devicetree.dtb**: Binary blob containing the specification of what hardware
  is present in the system.
- **uImage**: Linux kernel image is the computer program that provides OS
  functionality.

Get BOOT.BIN from HDL project
"""""""""""""""""""""""""""""

To achieve high performance with AD4134 and similar ADCs, the hardware platform
must have an integrated FPGA. To configure the FPGA to properly support them,
ADI engineers provide :git+hdl:`HDL reference projects </>` from which one may
use :git+hdl:`ad4134_fmc <tree/main/projects/ad4134_fmc+>`,
:git+hdl:`ad7134_fmc <tree/main/projects/ad7134_fmc+>`, or
:git+hdl:`cn0561 <tree/main/projects/cn0561+>`.

Follow the build instructions on the :external+hdl:ref:`build_hdl` page to build
the appropriate HDL project and generate a BOOT.BIN file from that.

Get uImage and devicetree.dtb from Linux project
""""""""""""""""""""""""""""""""""""""""""""""""

Follow the
:dokuwiki:`Linux build guide </resources/tools-software/linux-build/generic/zynq>`
to build a new Linux kernel image and devicetree blob. After that, replace
Kuiper Linux image with the newly built *uImage* and copy the proper .dtb file
your platform to the BOOT partition as *devicetree.dtb*.

Basic operation
~~~~~~~~~~~~~~~

Show channel scale
^^^^^^^^^^^^^^^^^^

**Description:** Scale for signed 24-bit samples from the IIO buffer, in
millivolts/code. There is no ``in_voltageX_raw`` attribute.

::

   root@analog:~# cat /sys/bus/iio/devices/iio:device0/in_voltage_scale
   0.000488281

Inspect the IIO device sysfs interface. The driver exposes only the shared
``in_voltage_scale``, ``in_voltage_sampling_frequency`` and
``in_voltage_sampling_frequency_available`` channel attributes. The sampling
frequency range is ``[10 1 1496000]`` Hz and defaults to 300000 Hz; stop the
buffer before changing it (writes fail while buffered capture is enabled).
